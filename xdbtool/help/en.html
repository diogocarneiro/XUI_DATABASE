Getting started

  1. In Data source, pick a live database (MySQL/MariaDB) or a .sql dump file and press Connect / Load.
  2. The app identifies the panel and lists its tables with category, rows and columns. Tick the tables you want to work on (All / None / filter).
  3. Use the tabs on the right. The log at the bottom shows what is happening.

Blue buttons are the main actions; buttons outlined in red write to a server (import, restore, migrate, repair) and always ask for confirmation.

Data source

  • Live MySQL / MariaDB — host, port, user, password and database (for example xui). Needed for maintenance and for exporting CREATE TABLE.
  • Dump file — reads a .sql or .sql.gz without a server. The whole file is read into memory; for huge dumps use a live connection.
  • Profiles — Save stores the connection (SSH included) for next time. The password is only stored if you tick Save password in profile.

SSH connections

XUI's MariaDB only accepts connections from the server itself (error 1130 from your PC). Connect via offers three modes:

  • Direct MySQL connection — only if the server accepts your IP.
  • SSH + server MySQL socket — the simplest on XUI: logs in like mysql -uroot on the server, without a MySQL password. Give the SSH host, user and password; leave the MySQL password empty.
  • SSH tunnel to MySQL TCP 127.0.0.1 — for MySQL users with a password, such as the one in /home/xui/config/config.ini.

The Templates and Migrate / Restore tabs offer the same choice.

Export / Backup

Exports the ticked tables as JSON, CSV or SQL (with CREATE TABLE when the source is live). Redact password/secret-like columns hides those values, useful when sharing exports. Always take an SQL backup before repairing, migrating or importing.

Maintenance

Runs Check, Repair, Analyze or Optimize on the ticked tables (live connection only). Check & auto-repair broken tables checks them all and repairs only the damaged ones.

Integrity

The panels declare no links between their tables, so deleting a category, bouquet, server or line in the panel (or by hand) can leave rows pointing at something that no longer exists. Check integrity reads the whole database (live or dump) and lists:

  • rows that point to missing ids — streams of a deleted category, bouquets listing deleted streams, lines with deleted bouquets, MAG/Enigma2 devices of deleted lines, episodes of a deleted series, streams on a deleted server…;
  • the same id repeated inside a bouquet or line list, and lists that are not valid JSON;
  • usernames, MACs and access codes used by more than one row;
  • streams assigned to no server (they cannot play) and episodes linked to no series.

Each problem shows its fix: delete these rows (a row that only makes sense with what was deleted), clear the reference, remove the missing ids from the list or remove the repeated ids. The others are report only: review them by hand. Untick what you do not want to fix, then:

  • Save fix script… — writes the SQL (one transaction) to run on the server; the only option for a dump file;
  • Apply selected fixes — live connection: backs up the affected tables as SQL in the export folder (integrity-DATE), applies everything in one transaction and runs the check again. Run it again until nothing fixable is left: deleting a device, for example, can uncover its old events.

When the referenced table is empty (for example a partial dump without servers) the problem is reported but never fixed automatically. Command line: check --dump file.sql --fix-sql fix.sql, or check --host … --fix.

Renumber IDs

After old channels are deleted the remaining streams keep their high ids (the first channel is 300, say). Renumber IDs gives every stream — channels, movies, radios and episodes — consecutive ids again from First new id (1), keeping the current order or putting live channels first. Every reference is updated with it: servers, episodes, options, bouquets, MAG favourites, last channel watched and every stream_id column (logs, queue…).

  1. Run Integrity and apply its fixes: references to deleted streams whose ids would be reused block the renumbering (in logs they are simply cleared).
  2. Click Preview: it shows the old and new id range and how many rows change in each table.
  3. Stop the streams, then Renumber now (live connection; type the database name to confirm). The affected tables are backed up as SQL to the export folder (renumber-DATE) and everything runs in one transaction. For a dump, use Save SQL script….
  4. Save file-rename script… and run it on the server as root (bash renumber_files.sh): it renames movie/episode files and TV archive folders named by id.
  5. Restart XUI. Playback URLs change (…/live/user/pass/ID.ts): clients must reload their M3U playlist.

Command line: renumber --dump file.sql --sql-out renumber.sql --files-script files.sh, or renumber --host … --apply.

Templates / New DB

A template is the schema of a clean panel installation. Register base .sql stores it once; Create database from template then creates a new, empty database on a server (for example xui_test). Do not use the live panel's database name (xui): with DROP ticked it would be replaced — the app refuses and asks you to type the name to confirm.

Migrate / Restore

  • Migrate the loaded source — copies rows into a target database column by column (only columns present on both sides). Build plan shows what will be copied; Dry run writes a .sql instead of writing to the server.
  • Restore a dump — runs a .sql as-is on the target server, optionally creating the database first.

Migrating to XUI (older panels)

To bring an Xtream UI, ZapX, StreamCreed or Xtream Codes v2 panel to XUI.one with XUI's own Database Migration page:

  1. In the XUI Migration tab choose SSH mode, the XUI server and the old dump.
  2. Check dump, then Load into xui_migrate (or write a script to run on the server).
  3. In the XUI panel: Database Migration → Migrate Database.

Only the xui_migrate database is written; the live xui database is not touched. Log rows are skipped because XUI does not migrate them.

Importing an XUI.one backup into another XUI

XUI's migration page refuses XUI backups ("Can't migrate from XUI to XUI"). This feature imports straight into the xui database over SSH:

  • Restore — choose what to bring: channels, movies, series, radio, bouquets, lines and devices, resellers, EPG, block lists. Only the chosen kinds are replaced; the rest stays as it is.
  • Streams — move them all to this XUI's main server (ideal for a single server) or add the old load balancers.
  • System — by default the new XUI keeps its own servers, settings and access codes; each can be imported separately.
  • Before anything changes, the current xui is backed up on the server (/root/xui-before-import-*.sql.gz) and everything runs in one transaction.
  • At the end a rescue access (access code + admin user) is created and every panel URL is listed. Save the password and delete the rescue access once you are in.

Always use Preview XUI import first.

Safety

  • Credentials are copied as they are; password hashes are never decrypted.
  • The app refuses to DROP a database holding panel data without typed confirmation.
  • MySQL passwords sent over SSH go in a protected temporary file, never on the command line.

Theme and language

Theme: Automatic (follows the system), Light or Dark. Language: Português, English, Français, Español, Italiano. Both choices are remembered.

Updates

Help → Check for updates compares your version with the latest GitHub release and shows what is new. Update now downloads the new version, verifies its SHA-256 and installs it (the app restarts). On the command line: update --check and update. All versions: {releases}

Common problems

  • 1130 "Host … is not allowed" — MySQL does not accept your IP: use an SSH mode.
  • 1045 "Access denied … (using password: NO)" as root — root only logs in through the socket: choose SSH + server MySQL socket.
  • "Can't migrate from XUI to XUI" — the file is an XUI.one backup: use Importing an XUI backup.
  • An imported URL does not open — restart XUI or save the access code again in the panel so nginx reloads it.
