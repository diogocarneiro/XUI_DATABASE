Guía de XUI DB Tool

Versión {version}. Para administradores de paneles IPTV (XUI.one, Xtream UI, StreamCreed, ZapX, Xtream Codes v2) que gestionan bases de datos propias o que están autorizados a gestionar.

Empezar

  1. En Origen de los datos, elige una base en vivo (MySQL/MariaDB) o un archivo de dump .sql y pulsa Conectar / Cargar.
  2. La app identifica el panel y lista sus tablas con categoría, filas y columnas. Marca las tablas con las que quieres trabajar (Todos / Ninguno / filtro).
  3. Usa las pestañas de la derecha. El registro de abajo muestra lo que está pasando.

Los botones azules son las acciones principales; los botones con borde rojo escriben en un servidor (importar, restaurar, migrar, reparar) y siempre piden confirmación.

Origen de los datos

  • MySQL / MariaDB en vivo — host, puerto, usuario, contraseña y base de datos (por ejemplo xui). Necesario para el mantenimiento y para exportar el CREATE TABLE.
  • Archivo de dump — lee un .sql o .sql.gz sin servidor. El archivo se lee entero en memoria; para dumps enormes usa la conexión en vivo.
  • Perfiles — Guardar recuerda la conexión (incluido SSH). La contraseña solo se guarda si marcas Guardar la contraseña en el perfil.

Conexión SSH

El MariaDB de XUI solo acepta conexiones del propio servidor (error 1130 desde tu PC). Conectar vía ofrece tres modos:

  • Conexión MySQL directa — solo si el servidor acepta tu IP.
  • SSH + socket MySQL del servidor — lo más sencillo en XUI: entra como mysql -uroot en el servidor, sin contraseña MySQL. Indica host, usuario y contraseña SSH; deja vacía la contraseña MySQL.
  • Túnel SSH a MySQL TCP 127.0.0.1 — para usuarios MySQL con contraseña, como el de /home/xui/config/config.ini.

Las pestañas Plantillas y Migrar / Restaurar ofrecen la misma elección.

Ver y editar datos

Haz doble clic en una tabla de la lista Tablas (o selecciónala y pulsa Ver datos…) para abrir sus filas en una ventana aparte; puedes tener varias tablas abiertas a la vez. Funciona con bases de datos en vivo y con dumps — en vivo, la búsqueda, la ordenación y la paginación se hacen en el servidor, así que incluso tablas con millones de filas se abren al instante.

  • Buscar encuentra las filas que contienen el texto (sin distinguir mayúsculas) en todas las columnas, o en la columna elegida al lado; Limpiar vuelve a mostrar todo.
  • Haz clic en el encabezado de una columna para ordenar; otro clic para orden descendente.
  • « ‹ › » cambian de página; elige de 50 a 1000 filas por página.
  • Doble clic en una fila (o Detalles de la fila…) muestra todas las columnas completas, con las listas JSON, como los canales de un bouquet, formateadas.
  • Ctrl+C copia las celdas seleccionadas (separadas por tabuladores, listas para una hoja de cálculo).
  • Contraseñas, hashes, tokens y claves se muestran como ••••••; marca Mostrar contraseñas/claves para verlos.

Línea de comandos: view streams --dump archivo.sql --search sport --columns id,stream_display_name --order id (--json para JSON).

Editar (conexión en vivo)

Marca Modo edición para cambiar la tabla en el servidor. Está disponible en una conexión en vivo para tablas con clave primaria (la clave en sí no se puede editar — para los ids de los streams usa Renumerar ids).

  • Haz doble clic en una celda (o empieza a escribir) para cambiarla; las celdas editadas se ponen amarillas.
  • Añadir fila añade una fila vacía (verde): rellena las celdas que necesites, las demás reciben el valor predeterminado — (auto) marca el id que asigna el servidor. Duplicar copia las filas seleccionadas como filas nuevas, útil para crear un canal parecido a otro.
  • Eliminar / restaurar marca las filas seleccionadas para eliminar (rojo, tachadas); otro clic las conserva. Poner NULL vacía las celdas seleccionadas.
  • Importar CSV/JSON… añade las filas de un archivo: un CSV con línea de encabezado (separado por comas, punto y coma o tabuladores — los archivos de Excel guardados como CSV funcionan) o una lista JSON de objetos. Las columnas se asocian por nombre; las desconocidas se indican y se ignoran; las celdas CSV vacías reciben el valor predeterminado.
  • No se escribe nada hasta Guardar cambios…: muestra qué va a cambiar y el SQL, y guarda todo en una sola transacción. Si el panel modificó alguna de esas filas entretanto, no se guarda nada. Se escribe en la carpeta de exportación un script para deshacer (edit-TABLA-FECHA.undo.sql) con los valores anteriores — ejecútalo con mysql o en Migrar / Restaurar para volver atrás.

Los valores se comprueban al escribir: números enteros en columnas numéricas, JSON válido donde la celda tenía una lista JSON (canales de bouquets, categorías…), y un aviso antes de que un texto simple sustituya un hash de contraseña. Cambiar de página pide descartar los cambios sin guardar. Línea de comandos: edit streams --host … --key id=300 --set stream_display_name="SPORT HD", --delete, --insert --set …, --import filas.csv, y --dry-run para ver solo el SQL.

Exportar / Copia

Exporta las tablas marcadas en JSON, CSV o SQL (con CREATE TABLE si el origen está en vivo). Ocultar columnas de contraseñas/secretos esconde esos valores, útil para compartir exportaciones. Haz siempre una copia SQL antes de reparar, migrar o importar.

Mantenimiento

Ejecuta Comprobar, Reparar, Analizar u Optimizar en las tablas marcadas (solo con conexión en vivo). Comprobar y reparar automáticamente las comprueba todas y repara solo las dañadas.

Integridad

Los paneles no declaran vínculos entre sus tablas, así que borrar una categoría, bouquet, servidor o línea en el panel (o a mano) puede dejar filas que apuntan a algo que ya no existe. Verificar integridad lee toda la base de datos (en vivo o dump) y muestra:

  • filas que apuntan a ids inexistentes — streams de una categoría borrada, bouquets con streams borrados, líneas con bouquets borrados, dispositivos MAG/Enigma2 de líneas borradas, episodios de una serie borrada, streams en un servidor borrado…;
  • el mismo id repetido dentro de la lista de un bouquet o línea, y listas que no son JSON válido;
  • usuarios, MAC y códigos de acceso usados por más de una fila;
  • streams sin ningún servidor asignado (no se pueden reproducir) y episodios sin serie.

Cada problema muestra su corrección: eliminar estas filas, borrar la referencia, quitar de la lista los ids inexistentes o quitar los ids repetidos. Los demás son solo informe: revísalos a mano. Desmarca lo que no quieras corregir y luego:

  • Guardar script de corrección… — escribe el SQL (una transacción) para ejecutarlo en el servidor; es la única opción para un archivo dump;
  • Aplicar correcciones seleccionadas — conexión en vivo: hace una copia SQL de las tablas afectadas en la carpeta de exportación (integrity-FECHA), aplica todo en una transacción y repite la verificación. Repite hasta que no quede nada corregible: borrar un dispositivo, por ejemplo, puede revelar sus eventos antiguos.

Si la tabla referida está vacía (por ejemplo, un dump parcial sin servers) el problema se informa pero nunca se corrige automáticamente. Línea de comandos: check --dump archivo.sql --fix-sql fix.sql, o check --host … --fix.

Renumerar ids

Tras borrar canales antiguos, los streams que quedan conservan ids altos (por ejemplo, el primer canal es el 300). Renumerar ids vuelve a dar a todos los streams — canales, películas, radios y episodios — ids consecutivos desde Primer id nuevo (1), manteniendo el orden actual o poniendo primero los canales en vivo. Se actualizan todas las referencias: servidores, episodios, opciones, bouquets, favoritos MAG, último canal visto y cada columna stream_id (registros, cola…).

  1. Ejecuta Integridad y aplica sus correcciones: las referencias a streams borrados cuyos ids se reutilizarían bloquean la renumeración (en los registros simplemente se borran).
  2. Haz clic en Vista previa: muestra el rango de ids antiguo y nuevo y cuántas filas cambian en cada tabla.
  3. Detén los streams y pulsa Renumerar ahora (conexión en vivo; escribe el nombre de la base de datos para confirmar). Se hace una copia SQL de las tablas afectadas en la carpeta de exportación (renumber-FECHA) y todo se ejecuta en una transacción. Para un dump, usa Guardar script SQL….
  4. Guardar script de renombrado… y ejecútalo en el servidor como root (bash renumber_files.sh): renombra los archivos de películas/episodios y las carpetas del archivo de TV que llevan el id en el nombre.
  5. Reinicia XUI. Las URL de reproducción cambian (…/live/user/pass/ID.ts): los clientes deben recargar su lista M3U.

Línea de comandos: renumber --dump archivo.sql --sql-out renumber.sql --files-script files.sh, o renumber --host … --apply.

Plantillas / Nueva BD

Una plantilla es el esquema de una instalación limpia de un panel. Registrar .sql base la guarda una vez; después Crear base de datos desde la plantilla crea una base nueva y vacía en un servidor (por ejemplo xui_test). No uses el nombre de la base del panel en producción (xui): con DROP marcado se sustituiría — la app lo rechaza y pide que escribas el nombre para confirmar.

Reconstruir una base de datos desde un dump

Úsalo cuando una copia tiene un esquema antiguo, dañado o de otra versión: la nueva base recibe el esquema limpio de la plantilla y solo los datos de las tablas que elijas.

  1. Carga el dump (o una base en vivo) en Origen de los datos.
  2. Marca en la lista de la izquierda las tablas a copiar (por ejemplo, desmarca los logs).
  3. Elige la plantilla — la más parecida se selecciona automáticamente — y escribe el nombre de la nueva base.
  4. Vista previa de la reconstrucción muestra en el registro qué pasa con cada tabla.
  5. Reconstruir → crear la nueva base de datos la crea en el servidor de destino, o Guardar como archivo .sql local… guarda toda la nueva base en un archivo en este equipo (.sql, o .sql.gz comprimido) — no necesita servidor.

El archivo local: con un nombre en Nueva base de datos crea él mismo esa base (mysql -u root -p < archivo); en blanco, es un dump portátil sin nombre de base dentro — impórtalo en cualquier base vacía con phpMyAdmin → Importar, con Migrar / Restaurar (marca Crear primero la base de datos de destino) o con mysql -u root -p BASE < archivo. También se puede abrir de nuevo aquí como Archivo de dump SQL.

Las columnas coinciden por nombre: las que solo existen en el dump se descartan y las columnas nuevas de la plantilla reciben su valor predeterminado. Una tabla marcada recibe las filas del dump; una tabla no marcada queda vacía. Filas propias de la plantilla decide dónde se usan las filas de la plantilla: por defecto solo en las tablas que el dump no tiene (nuevas en esa versión) y nunca líneas, streams ni logs de una plantilla; En todas las tablas que no vienen del origen rellena también las no marcadas con las filas de la plantilla; Ninguna usa solo el esquema. La vista previa muestra el tamaño de las filas de la plantilla conservadas y omitidas, y avisa cuando una plantilla no es una instalación limpia (la base de un panel real, a menudo de cientos de MB). Por eso marca también las tablas de configuración que necesites (ajustes, grupos, paquetes, tipos de stream…). Las tablas que la plantilla no tiene se omiten. Las filas se copian en una sola transacción y los hashes de las contraseñas se copian tal cual. La app rechaza una base que ya tenga tablas, salvo que DROP esté marcado.

Migrar / Restaurar

  • Migrar el origen cargado — copia las filas a una base de destino columna a columna (solo las columnas que existen en ambos lados). Generar plan muestra antes lo que se copiará; la simulación escribe un .sql en lugar de escribir en el servidor.
  • Restaurar un dump — ejecuta un .sql tal cual en el servidor de destino, opcionalmente creando antes la base.

Migración a XUI (paneles antiguos)

Para llevar un panel Xtream UI, ZapX, StreamCreed o Xtream Codes v2 a XUI.one con la página Database Migration del propio XUI:

  1. En la pestaña Migración XUI, elige el modo SSH, el servidor XUI y el dump antiguo.
  2. Comprobar dump y después Cargar en xui_migrate (o escribe un script para ejecutar en el servidor).
  3. En el panel XUI: Database Migration → Migrate Database.

Solo se escribe la base xui_migrate; la base xui en producción no se toca. Las filas de registros se omiten porque XUI no las migra.

Importar una copia XUI.one en otro XUI

La página de migración de XUI rechaza las copias XUI ("Can't migrate from XUI to XUI"). Esta función importa directamente en la base xui, por SSH:

  • Restaurar — elige qué traer: canales, películas, series, radios, bouquets, líneas y dispositivos, revendedores, EPG, listas de bloqueo. Solo se sustituyen los tipos elegidos; el resto se queda como está.
  • Streams — moverlos todos al servidor principal de este XUI (ideal para un solo servidor) o añadir los balanceadores antiguos.
  • Sistema — por defecto el XUI nuevo conserva sus servidores, ajustes y códigos de acceso; cada uno se puede importar por separado.
  • Antes de cambiar nada se hace una copia de la xui actual en el servidor (/root/xui-before-import-*.sql.gz) y todo se ejecuta en una transacción.
  • Al final se crea un acceso de rescate (código de acceso + usuario admin) y se muestran todas las URL del panel. Guarda la contraseña y elimina el acceso cuando hayas entrado.

Usa siempre primero Vista previa de la importación XUI.

Seguridad

  • Las credenciales se copian tal cual; los hashes de contraseñas nunca se descifran.
  • La app rechaza hacer DROP de una base con datos de panel sin confirmación escrita.
  • Las contraseñas MySQL enviadas por SSH van en un archivo temporal protegido, nunca en la línea de comandos.

Tema e idioma

Tema: Automático (sigue al sistema), Claro u Oscuro. Idioma: Português, English, Français, Español, Italiano. Ambas elecciones se recuerdan.

Problemas comunes

  • 1130 "Host … is not allowed" — MySQL no acepta tu IP: usa un modo SSH.
  • 1045 "Access denied … (using password: NO)" con root — root solo entra por el socket: elige SSH + socket MySQL del servidor.
  • "Can't migrate from XUI to XUI" — el archivo es una copia de XUI.one: usa Importar copia XUI.
  • Una URL importada no abre — reinicia XUI o vuelve a guardar el código de acceso en el panel para que nginx lo recargue.
