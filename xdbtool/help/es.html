Guía de XUI DB Tool

Empezar

  1. En Origen de los datos, elige una base en vivo (MySQL/MariaDB) o un archivo de dump .sql y pulsa Conectar / Cargar.
  2. La app identifica el panel y lista sus tablas con categoría, filas y columnas. Marca las tablas con las que quieres trabajar (Todos / Ninguno / filtro).
  3. Usa las pestañas de la derecha. El registro de abajo muestra lo que está pasando.

Los botones azules son las acciones principales; los botones con borde rojo escriben en un servidor (importar, restaurar, migrar, reparar) y siempre piden confirmación.

Origen de los datos

  • MySQL / MariaDB en vivo — host, puerto, usuario, contraseña y base de datos (por ejemplo xui). Necesario para el mantenimiento y para exportar el CREATE TABLE.
  • Archivo de dump — lee un .sql o .sql.gz sin servidor. El archivo se lee entero en memoria; para dumps enormes usa la conexión en vivo.
  • Perfiles — Guardar recuerda la conexión (incluido SSH). La contraseña solo se guarda si marcas Guardar la contraseña en el perfil.

Conexión SSH

El MariaDB de XUI solo acepta conexiones del propio servidor (error 1130 desde tu PC). Conectar vía ofrece tres modos:

  • Conexión MySQL directa — solo si el servidor acepta tu IP.
  • SSH + socket MySQL del servidor — lo más sencillo en XUI: entra como mysql -uroot en el servidor, sin contraseña MySQL. Indica host, usuario y contraseña SSH; deja vacía la contraseña MySQL.
  • Túnel SSH a MySQL TCP 127.0.0.1 — para usuarios MySQL con contraseña, como el de /home/xui/config/config.ini.

Las pestañas Plantillas y Migrar / Restaurar ofrecen la misma elección.

Exportar / Copia

Exporta las tablas marcadas en JSON, CSV o SQL (con CREATE TABLE si el origen está en vivo). Ocultar columnas de contraseñas/secretos esconde esos valores, útil para compartir exportaciones. Haz siempre una copia SQL antes de reparar, migrar o importar.

Mantenimiento

Ejecuta Comprobar, Reparar, Analizar u Optimizar en las tablas marcadas (solo con conexión en vivo). Comprobar y reparar automáticamente las comprueba todas y repara solo las dañadas.

Plantillas / Nueva BD

Una plantilla es el esquema de una instalación limpia de un panel. Registrar .sql base la guarda una vez; después Crear base de datos desde la plantilla crea una base nueva y vacía en un servidor (por ejemplo xui_test). No uses el nombre de la base del panel en producción (xui): con DROP marcado se sustituiría — la app lo rechaza y pide que escribas el nombre para confirmar.

Migrar / Restaurar

  • Migrar el origen cargado — copia las filas a una base de destino columna a columna (solo las columnas que existen en ambos lados). Generar plan muestra antes lo que se copiará; la simulación escribe un .sql en lugar de escribir en el servidor.
  • Restaurar un dump — ejecuta un .sql tal cual en el servidor de destino, opcionalmente creando antes la base.

Migración a XUI (paneles antiguos)

Para llevar un panel Xtream UI, ZapX, StreamCreed o Xtream Codes v2 a XUI.one con la página Database Migration del propio XUI:

  1. En la pestaña Migración XUI, elige el modo SSH, el servidor XUI y el dump antiguo.
  2. Comprobar dump y después Cargar en xui_migrate (o escribe un script para ejecutar en el servidor).
  3. En el panel XUI: Database Migration → Migrate Database.

Solo se escribe la base xui_migrate; la base xui en producción no se toca. Las filas de registros se omiten porque XUI no las migra.

Importar una copia XUI.one en otro XUI

La página de migración de XUI rechaza las copias XUI ("Can't migrate from XUI to XUI"). Esta función importa directamente en la base xui, por SSH:

  • Restaurar — elige qué traer: canales, películas, series, radios, bouquets, líneas y dispositivos, revendedores, EPG, listas de bloqueo. Solo se sustituyen los tipos elegidos; el resto se queda como está.
  • Streams — moverlos todos al servidor principal de este XUI (ideal para un solo servidor) o añadir los balanceadores antiguos.
  • Sistema — por defecto el XUI nuevo conserva sus servidores, ajustes y códigos de acceso; cada uno se puede importar por separado.
  • Antes de cambiar nada se hace una copia de la xui actual en el servidor (/root/xui-before-import-*.sql.gz) y todo se ejecuta en una transacción.
  • Al final se crea un acceso de rescate (código de acceso + usuario admin) y se muestran todas las URL del panel. Guarda la contraseña y elimina el acceso cuando hayas entrado.

Usa siempre primero Vista previa de la importación XUI.

Seguridad

  • Las credenciales se copian tal cual; los hashes de contraseñas nunca se descifran.
  • La app rechaza hacer DROP de una base con datos de panel sin confirmación escrita.
  • Las contraseñas MySQL enviadas por SSH van en un archivo temporal protegido, nunca en la línea de comandos.

Tema e idioma

Tema: Automático (sigue al sistema), Claro u Oscuro. Idioma: Português, English, Français, Español, Italiano. Ambas elecciones se recuerdan.

Problemas comunes

  • 1130 "Host … is not allowed" — MySQL no acepta tu IP: usa un modo SSH.
  • 1045 "Access denied … (using password: NO)" con root — root solo entra por el socket: elige SSH + socket MySQL del servidor.
  • "Can't migrate from XUI to XUI" — el archivo es una copia de XUI.one: usa Importar copia XUI.
  • Una URL importada no abre — reinicia XUI o vuelve a guardar el código de acceso en el panel para que nginx lo recargue.
