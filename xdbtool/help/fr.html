Démarrer

  1. Dans Source des données, choisissez une base en direct (MySQL/MariaDB) ou un fichier de dump .sql, puis cliquez sur Connecter / Charger.
  2. L'application identifie le panneau et liste ses tables avec catégorie, lignes et colonnes. Cochez les tables à traiter (Tous / Aucun / filtre).
  3. Utilisez les onglets de droite. Le journal en bas montre ce qui se passe.

Les boutons bleus sont les actions principales ; les boutons au contour rouge écrivent sur un serveur (import, restauration, migration, réparation) et demandent toujours une confirmation.

Source des données

  • MySQL / MariaDB en direct — hôte, port, utilisateur, mot de passe et base (par exemple xui). Nécessaire pour la maintenance et pour exporter le CREATE TABLE.
  • Fichier de dump — lit un .sql ou .sql.gz sans serveur. Le fichier entier est chargé en mémoire ; pour les très gros dumps, utilisez la connexion en direct.
  • Profils — Enregistrer mémorise la connexion (SSH compris). Le mot de passe n'est enregistré que si vous cochez Enregistrer le mot de passe dans le profil.

Connexion SSH

Le MariaDB de XUI n'accepte que les connexions du serveur lui-même (erreur 1130 depuis votre PC). Connexion via propose trois modes :

  • Connexion MySQL directe — seulement si le serveur accepte votre IP.
  • SSH + socket MySQL du serveur — le plus simple sur XUI : se connecte comme mysql -uroot sur le serveur, sans mot de passe MySQL. Indiquez l'hôte, l'utilisateur et le mot de passe SSH ; laissez le mot de passe MySQL vide.
  • Tunnel SSH vers MySQL TCP 127.0.0.1 — pour les utilisateurs MySQL avec mot de passe, comme celui de /home/xui/config/config.ini.

Les onglets Modèles et Migrer / Restaurer proposent le même choix.

Voir et modifier les données

Double-cliquez sur une table de la liste Tables (ou sélectionnez-la et cliquez sur Voir les données…) pour ouvrir ses lignes dans une fenêtre séparée ; plusieurs tables peuvent être ouvertes en même temps. Fonctionne sur les bases en direct et les dumps — en direct, la recherche, le tri et la pagination s'exécutent sur le serveur, donc même les tables de millions de lignes s'ouvrent aussitôt.

  • Rechercher trouve les lignes contenant le texte (sans tenir compte de la casse) dans toutes les colonnes, ou dans la colonne choisie à côté ; Effacer réaffiche tout.
  • Cliquez sur l'en-tête d'une colonne pour trier ; cliquez à nouveau pour l'ordre décroissant.
  • « ‹ › » changent de page ; choisissez de 50 à 1000 lignes par page.
  • Double-cliquez sur une ligne (ou Détails de la ligne…) pour voir toutes les colonnes en entier, avec les listes JSON, comme les chaînes d'un bouquet, mises en forme.
  • Ctrl+C copie les cellules sélectionnées (séparées par des tabulations, prêtes pour un tableur).
  • Les mots de passe, hashes, jetons et clés s'affichent en •••••• ; cochez Afficher mots de passe/clés pour les voir.

Ligne de commande : view streams --dump fichier.sql --search sport --columns id,stream_display_name --order id (--json pour du JSON).

Modification (connexion en direct)

Cochez Mode édition pour modifier la table sur le serveur. Disponible en connexion directe pour les tables ayant une clé primaire (la clé elle-même n'est pas modifiable — utilisez Renuméroter les ids pour les ids des streams).

  • Double-cliquez sur une cellule (ou commencez à taper) pour la modifier ; les cellules modifiées passent en jaune.
  • Ajouter une ligne ajoute une ligne vide (verte) : remplissez les cellules utiles, les autres prennent la valeur par défaut — (auto) marque l'id attribué par le serveur. Dupliquer copie les lignes sélectionnées en nouvelles lignes, pratique pour créer une chaîne semblable à une autre.
  • Supprimer / rétablir marque les lignes sélectionnées pour suppression (rouge, barrées) ; cliquez à nouveau pour les garder. Mettre à NULL vide les cellules sélectionnées.
  • Importer CSV/JSON… ajoute les lignes d'un fichier : un CSV avec ligne d'en-tête (séparé par virgules, points-virgules ou tabulations — les fichiers Excel enregistrés en CSV fonctionnent) ou une liste JSON d'objets. Les colonnes sont associées par nom ; les inconnues sont listées et ignorées ; les cellules CSV vides prennent la valeur par défaut.
  • Rien n'est écrit avant Enregistrer les modifications… : il montre ce qui va changer et le SQL, puis enregistre tout dans une transaction. Si le panel a modifié une de ces lignes entre-temps, rien n'est enregistré. Un script d'annulation (edit-TABLE-DATE.undo.sql) avec les valeurs précédentes est écrit dans le dossier d'export — exécutez-le avec mysql ou Migrer / Restaurer pour revenir en arrière.

Les valeurs sont vérifiées à la saisie : nombres entiers pour les colonnes numériques, JSON valide là où la cellule contenait une liste JSON (chaînes des bouquets, catégories…), et un avertissement avant qu'un texte simple ne remplace un hash de mot de passe. Changer de page demande d'abandonner les modifications non enregistrées. Ligne de commande : edit streams --host … --key id=300 --set stream_display_name="SPORT HD", --delete, --insert --set …, --import lignes.csv, et --dry-run pour voir seulement le SQL.

Export / Sauvegarde

Exporte les tables cochées en JSON, CSV ou SQL (avec CREATE TABLE si la source est en direct). Masquer les colonnes de mots de passe/secrets cache ces valeurs, utile pour partager un export. Faites toujours une sauvegarde SQL avant de réparer, migrer ou importer.

Maintenance

Exécute Vérifier, Réparer, Analyser ou Optimiser sur les tables cochées (connexion en direct uniquement). Vérifier et réparer automatiquement vérifie toutes les tables et ne répare que celles qui sont endommagées.

Intégrité

Les panels ne déclarent aucun lien entre leurs tables : supprimer une catégorie, un bouquet, un serveur ou une ligne dans le panel (ou à la main) peut laisser des lignes pointant vers quelque chose qui n'existe plus. Vérifier l'intégrité lit toute la base (en direct ou dump) et liste :

  • les lignes qui pointent vers des ids inexistants — streams d'une catégorie supprimée, bouquets listant des streams supprimés, lignes avec des bouquets supprimés, appareils MAG/Enigma2 de lignes supprimées, épisodes d'une série supprimée, streams sur un serveur supprimé… ;
  • le même id répété dans la liste d'un bouquet ou d'une ligne, et les listes qui ne sont pas du JSON valide ;
  • les noms d'utilisateur, MAC et codes d'accès utilisés par plusieurs lignes ;
  • les streams sans serveur (ils ne peuvent pas être lus) et les épisodes sans série.

Chaque problème indique sa correction : supprimer ces lignes, effacer la référence, retirer de la liste les ids manquants ou retirer les ids répétés. Les autres sont signalés seulement : vérifiez-les à la main. Décochez ce que vous ne voulez pas corriger, puis :

  • Enregistrer le script de correction… — écrit le SQL (une transaction) à exécuter sur le serveur ; seule option pour un fichier dump ;
  • Appliquer les corrections cochées — connexion en direct : sauvegarde les tables concernées en SQL dans le dossier d'export (integrity-DATE), applique tout dans une transaction et relance la vérification. Relancez jusqu'à ce qu'il ne reste rien de corrigeable : supprimer un appareil, par exemple, peut révéler ses anciens événements.

Si la table référencée est vide (par exemple un dump partiel sans servers), le problème est signalé mais jamais corrigé automatiquement. Ligne de commande : check --dump fichier.sql --fix-sql fix.sql, ou check --host … --fix.

Renuméroter les ids

Après la suppression d'anciennes chaînes, les streams restants gardent des ids élevés (la première chaîne est la 300, par exemple). Renuméroter les ids redonne à tous les streams — chaînes, films, radios et épisodes — des ids consécutifs à partir de Premier nouvel id (1), en gardant l'ordre actuel ou en plaçant les chaînes en direct d'abord. Toutes les références sont mises à jour : serveurs, épisodes, options, bouquets, favoris MAG, dernière chaîne regardée et chaque colonne stream_id (journaux, file d'attente…).

  1. Lancez l'Intégrité et appliquez ses corrections : les références à des streams supprimés dont les ids seraient réutilisés bloquent la renumérotation (dans les journaux elles sont simplement effacées).
  2. Cliquez sur Aperçu : il montre l'ancienne et la nouvelle plage d'ids et le nombre de lignes modifiées par table.
  3. Arrêtez les streams, puis Renuméroter maintenant (connexion en direct ; tapez le nom de la base pour confirmer). Les tables concernées sont sauvegardées en SQL dans le dossier d'export (renumber-DATE) et tout s'exécute dans une transaction. Pour un dump, utilisez Enregistrer le script SQL….
  4. Enregistrer le script de renommage… et exécutez-le sur le serveur en root (bash renumber_files.sh) : il renomme les fichiers de films/épisodes et les dossiers d'archive TV nommés par id.
  5. Redémarrez XUI. Les URL de lecture changent (…/live/user/pass/ID.ts) : les clients doivent recharger leur playlist M3U.

Ligne de commande : renumber --dump fichier.sql --sql-out renumber.sql --files-script files.sh, ou renumber --host … --apply.

Modèles / Nouvelle BD

Un modèle est le schéma d'une installation propre d'un panneau. Enregistrer un .sql de base le mémorise une fois ; Créer la base de données depuis le modèle crée ensuite une base nouvelle et vide sur un serveur (par exemple xui_test). N'utilisez pas le nom de la base du panneau en production (xui) : avec DROP coché elle serait remplacée — l'application refuse et vous demande de saisir le nom pour confirmer.

Reconstruire une base de données depuis un dump

À utiliser quand une sauvegarde a un schéma ancien, endommagé ou d'une autre version : la nouvelle base reçoit le schéma propre du modèle et seulement les données des tables choisies.

  1. Chargez le dump (ou une base en direct) dans Source des données.
  2. Cochez dans la liste de gauche les tables à copier (par exemple, décochez les journaux).
  3. Choisissez le modèle — le plus proche est sélectionné automatiquement — et saisissez le nom de la nouvelle base.
  4. Aperçu de la reconstruction indique dans le journal ce qui arrive à chaque table.
  5. Reconstruire → créer la nouvelle base de données la crée sur le serveur cible, ou Enregistrer comme fichier .sql local… enregistre toute la nouvelle base dans un fichier sur cet ordinateur (.sql, ou .sql.gz compressé) — aucun serveur nécessaire.

Le fichier local : avec un nom dans Nouvelle base de données, il crée lui-même cette base (mysql -u root -p < fichier) ; laissé vide, c'est un dump portable sans nom de base — importez-le dans n'importe quelle base vide avec phpMyAdmin → Importer, avec Migrer / Restaurer (cochez Créer d'abord la base de données cible) ou avec mysql -u root -p BASE < fichier. Il peut aussi être rouvert ici comme Fichier de dump SQL.

Les colonnes correspondent par leur nom : celles présentes seulement dans le dump sont ignorées, les nouvelles colonnes du modèle reçoivent leur valeur par défaut. Une table cochée reçoit les lignes du dump ; une table non cochée reste vide. Lignes propres au modèle décide où les lignes du modèle sont utilisées : par défaut seulement dans les tables absentes du dump (nouvelles dans cette version), et jamais les lignes, flux ou journaux d'un modèle ; Dans toutes les tables non remplies depuis la source remplit aussi les tables non cochées avec les lignes du modèle ; Aucune ne prend que le schéma. L'aperçu indique la taille des lignes du modèle conservées et laissées de côté, et avertit quand un modèle n'est pas une installation propre (la base d'un vrai panneau, souvent des centaines de Mo). Cochez donc aussi les tables de configuration nécessaires (paramètres, groupes, offres, types de flux…). Les tables absentes du modèle sont ignorées. Les lignes sont copiées en une seule transaction ; les hachages des mots de passe sont copiés tels quels. L'application refuse une base qui contient déjà des tables, sauf si DROP est coché.

Migrer / Restaurer

  • Migrer la source chargée — copie les lignes vers une base cible colonne par colonne (seules les colonnes présentes des deux côtés). Construire le plan montre ce qui sera copié ; la simulation écrit un .sql au lieu d'écrire sur le serveur.
  • Restaurer un dump — exécute un .sql tel quel sur le serveur cible, en créant éventuellement la base d'abord.

Migration vers XUI (anciens panneaux)

Pour amener un panneau Xtream UI, ZapX, StreamCreed ou Xtream Codes v2 vers XUI.one avec la page Database Migration de XUI :

  1. Dans l'onglet Migration XUI, choisissez le mode SSH, le serveur XUI et l'ancien dump.
  2. Vérifier le dump, puis Charger dans xui_migrate (ou écrire un script à exécuter sur le serveur).
  3. Dans le panneau XUI : Database Migration → Migrate Database.

Seule la base xui_migrate est écrite ; la base xui en production n'est pas touchée. Les lignes de journaux sont ignorées car XUI ne les migre pas.

Importer une sauvegarde XUI.one dans un autre XUI

La page de migration de XUI refuse les sauvegardes XUI (« Can't migrate from XUI to XUI »). Cette fonction importe directement dans la base xui, via SSH :

  • Restaurer — choisissez quoi apporter : chaînes, films, séries, radios, bouquets, lignes et appareils, revendeurs, EPG, listes de blocage. Seuls les types choisis sont remplacés ; le reste ne change pas.
  • Flux — tous les déplacer vers le serveur principal de ce XUI (idéal pour un seul serveur) ou ajouter les anciens load balancers.
  • Système — par défaut, le nouveau XUI garde ses serveurs, paramètres et codes d'accès ; chacun peut être importé séparément.
  • Avant toute modification, la base xui actuelle est sauvegardée sur le serveur (/root/xui-before-import-*.sql.gz) et tout se fait dans une transaction.
  • À la fin, un accès de secours (code d'accès + utilisateur admin) est créé et toutes les URL du panneau sont affichées. Notez le mot de passe et supprimez l'accès une fois connecté.

Utilisez toujours d'abord Aperçu de l'import XUI.

Sécurité

  • Les identifiants sont copiés tels quels ; les hachages de mots de passe ne sont jamais déchiffrés.
  • L'application refuse un DROP d'une base contenant des données de panneau sans confirmation écrite.
  • Les mots de passe MySQL envoyés via SSH passent par un fichier temporaire protégé, jamais par la ligne de commande.

Problèmes courants

  • 1130 « Host … is not allowed » — MySQL n'accepte pas votre IP : utilisez un mode SSH.
  • 1045 « Access denied … (using password: NO) » avec root — root ne se connecte que par le socket : choisissez SSH + socket MySQL du serveur.
  • « Can't migrate from XUI to XUI » — le fichier est une sauvegarde XUI.one : utilisez Importer une sauvegarde XUI.
  • Une URL importée ne s'ouvre pas — redémarrez XUI ou enregistrez de nouveau le code d'accès dans le panneau pour que nginx le recharge.
