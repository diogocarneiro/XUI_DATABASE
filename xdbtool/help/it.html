Guida di XUI DB Tool

Versione {version}. Per amministratori di pannelli IPTV (XUI.one, Xtream UI, StreamCreed, ZapX, Xtream Codes v2) che gestiscono database di loro proprietà o che sono autorizzati a gestire.

Per iniziare

  1. In Origine dei dati scegli un database live (MySQL/MariaDB) o un file di dump .sql e premi Connetti / Carica.
  2. L'app identifica il pannello ed elenca le tabelle con categoria, righe e colonne. Seleziona le tabelle su cui lavorare (Tutti / Nessuno / filtro).
  3. Usa le schede a destra. Il log in basso mostra cosa sta succedendo.

I pulsanti blu sono le azioni principali; i pulsanti con bordo rosso scrivono su un server (importa, ripristina, migra, ripara) e chiedono sempre conferma.

Origine dei dati

  • MySQL / MariaDB live — host, porta, utente, password e database (per esempio xui). Necessario per la manutenzione e per esportare il CREATE TABLE.
  • File di dump — legge un .sql o .sql.gz senza server. L'intero file viene caricato in memoria; per dump enormi usa la connessione live.
  • Profili — Salva memorizza la connessione (SSH compreso). La password viene salvata solo se selezioni Salva la password nel profilo.

Connessione SSH

Il MariaDB di XUI accetta solo connessioni dal server stesso (errore 1130 dal tuo PC). Connetti tramite offre tre modalità:

  • Connessione MySQL diretta — solo se il server accetta il tuo IP.
  • SSH + socket MySQL del server — la più semplice su XUI: accede come mysql -uroot sul server, senza password MySQL. Indica host, utente e password SSH; lascia vuota la password MySQL.
  • Tunnel SSH verso MySQL TCP 127.0.0.1 — per utenti MySQL con password, come quello di /home/xui/config/config.ini.

Le schede Modelli e Migra / Ripristina offrono la stessa scelta.

Visualizza e modifica dati

Fai doppio clic su una tabella dell'elenco Tabelle (o selezionala e fai clic su Visualizza dati…) per aprirne le righe in una finestra separata; puoi tenere aperte più tabelle contemporaneamente. Funziona su database live e dump — in live ricerca, ordinamento e paginazione avvengono sul server, quindi anche tabelle con milioni di righe si aprono subito.

  • Cerca trova le righe che contengono il testo (senza distinguere maiuscole) in tutte le colonne, o nella colonna scelta accanto; Pulisci mostra di nuovo tutto.
  • Fai clic sull'intestazione di una colonna per ordinare; di nuovo per l'ordine decrescente.
  • « ‹ › » cambiano pagina; scegli da 50 a 1000 righe per pagina.
  • Doppio clic su una riga (o Dettagli della riga…) mostra tutte le colonne per intero, con le liste JSON, come i canali di un bouquet, formattate.
  • Ctrl+C copia le celle selezionate (separate da tabulazioni, pronte per un foglio di calcolo).
  • Password, hash, token e chiavi appaiono come ••••••; spunta Mostra password/chiavi per vederli.

Riga di comando: view streams --dump file.sql --search sport --columns id,stream_display_name --order id (--json per JSON).

Modifica (connessione live)

Spunta Modalità modifica per cambiare la tabella sul server. È disponibile con una connessione live per le tabelle con chiave primaria (la chiave stessa non è modificabile — per gli id degli stream usa Rinumera id).

  • Fai doppio clic su una cella (o inizia a scrivere) per modificarla; le celle modificate diventano gialle.
  • Aggiungi riga aggiunge una riga vuota (verde): compila le celle che ti servono, le altre ricevono il valore predefinito — (auto) indica l'id assegnato dal server. Duplica copia le righe selezionate come nuove righe, utile per creare un canale simile a un altro.
  • Elimina / ripristina segna le righe selezionate da eliminare (rosse, barrate); un altro clic le mantiene. Imposta NULL svuota le celle selezionate.
  • Importa CSV/JSON… aggiunge le righe di un file: un CSV con riga di intestazione (separato da virgole, punti e virgola o tabulazioni — i file Excel salvati come CSV funzionano) o una lista JSON di oggetti. Le colonne sono associate per nome; quelle sconosciute vengono elencate e ignorate; le celle CSV vuote ricevono il valore predefinito.
  • Non viene scritto nulla fino a Salva modifiche…: mostra cosa cambierà e l'SQL, poi salva tutto in un'unica transazione. Se nel frattempo il pannello ha modificato una di quelle righe, non viene salvato nulla. Nella cartella di esportazione viene scritto uno script di annullamento (edit-TABELLA-DATA.undo.sql) con i valori precedenti — eseguilo con mysql o in Migra / Ripristina per tornare indietro.

I valori vengono controllati mentre scrivi: numeri interi nelle colonne numeriche, JSON valido dove la cella conteneva una lista JSON (canali dei bouquet, categorie…), e un avviso prima che un testo semplice sostituisca un hash di password. Cambiare pagina chiede di scartare le modifiche non salvate. Riga di comando: edit streams --host … --key id=300 --set stream_display_name="SPORT HD", --delete, --insert --set …, --import righe.csv, e --dry-run per vedere solo l'SQL.

Esporta / Backup

Esporta le tabelle selezionate in JSON, CSV o SQL (con CREATE TABLE se l'origine è live). Oscura le colonne di password/segreti nasconde quei valori, utile per condividere le esportazioni. Esegui sempre un backup SQL prima di riparare, migrare o importare.

Manutenzione

Esegue Verifica, Ripara, Analizza o Ottimizza sulle tabelle selezionate (solo con connessione live). Verifica e ripara automaticamente le controlla tutte e ripara solo quelle danneggiate.

Integrità

I pannelli non dichiarano collegamenti tra le tabelle, quindi eliminare una categoria, un bouquet, un server o una linea nel pannello (o a mano) può lasciare righe che puntano a qualcosa che non esiste più. Verifica integrità legge tutto il database (live o dump) ed elenca:

  • righe che puntano a id inesistenti — stream di una categoria eliminata, bouquet con stream eliminati, linee con bouquet eliminati, dispositivi MAG/Enigma2 di linee eliminate, episodi di una serie eliminata, stream su un server eliminato…;
  • lo stesso id ripetuto nella lista di un bouquet o di una linea, e liste che non sono JSON valido;
  • nomi utente, MAC e codici di accesso usati da più righe;
  • stream non assegnati ad alcun server (non possono essere riprodotti) ed episodi senza serie.

Ogni problema mostra la sua correzione: elimina queste righe, azzera il riferimento, rimuovi dalla lista gli id mancanti o rimuovi gli id ripetuti. Gli altri sono solo segnalazione: rivedili a mano. Togli la spunta a ciò che non vuoi correggere, poi:

  • Salva script di correzione… — scrive l'SQL (una transazione) da eseguire sul server; è l'unica opzione per un file dump;
  • Applica le correzioni selezionate — connessione live: fa un backup SQL delle tabelle interessate nella cartella di esportazione (integrity-DATA), applica tutto in un'unica transazione e ripete la verifica. Ripeti finché non resta nulla da correggere: eliminare un dispositivo, ad esempio, può far emergere i suoi vecchi eventi.

Se la tabella di riferimento è vuota (ad esempio un dump parziale senza servers) il problema viene segnalato ma mai corretto automaticamente. Riga di comando: check --dump file.sql --fix-sql fix.sql, oppure check --host … --fix.

Rinumera id

Dopo aver eliminato vecchi canali, gli stream rimasti mantengono id alti (ad esempio il primo canale è il 300). Rinumera id ridà a tutti gli stream — canali, film, radio ed episodi — id consecutivi a partire da Primo nuovo id (1), mantenendo l'ordine attuale o mettendo prima i canali live. Tutti i riferimenti vengono aggiornati: server, episodi, opzioni, bouquet, preferiti MAG, ultimo canale visto e ogni colonna stream_id (log, coda…).

  1. Esegui Integrità e applica le correzioni: i riferimenti a stream eliminati i cui id verrebbero riutilizzati bloccano la rinumerazione (nei log vengono semplicemente azzerati).
  2. Fai clic su Anteprima: mostra l'intervallo di id vecchio e nuovo e quante righe cambiano in ogni tabella.
  3. Ferma gli stream, poi Rinumera ora (connessione live; digita il nome del database per confermare). Le tabelle interessate vengono salvate in SQL nella cartella di esportazione (renumber-DATA) e tutto viene eseguito in un'unica transazione. Per un dump usa Salva script SQL….
  4. Salva script di rinomina… ed eseguilo sul server come root (bash renumber_files.sh): rinomina i file di film/episodi e le cartelle dell'archivio TV con l'id nel nome.
  5. Riavvia XUI. Gli URL di riproduzione cambiano (…/live/user/pass/ID.ts): i client devono ricaricare la playlist M3U.

Riga di comando: renumber --dump file.sql --sql-out renumber.sql --files-script files.sh, oppure renumber --host … --apply.

Modelli / Nuovo DB

Un modello è lo schema di un'installazione pulita di un pannello. Registra .sql di base lo salva una volta; poi Crea database dal modello crea un database nuovo e vuoto su un server (per esempio xui_test). Non usare il nome del database del pannello in produzione (xui): con DROP selezionato verrebbe sostituito — l'app rifiuta e chiede di digitare il nome per confermare.

Migra / Ripristina

  • Migra l'origine caricata — copia le righe in un database di destinazione colonna per colonna (solo le colonne presenti su entrambi i lati). Genera piano mostra prima cosa verrà copiato; la simulazione scrive un .sql invece di scrivere sul server.
  • Ripristina un dump — esegue un .sql così com'è sul server di destinazione, creando eventualmente prima il database.

Migrazione a XUI (pannelli più vecchi)

Per portare un pannello Xtream UI, ZapX, StreamCreed o Xtream Codes v2 su XUI.one con la pagina Database Migration di XUI:

  1. Nella scheda Migrazione XUI scegli la modalità SSH, il server XUI e il vecchio dump.
  2. Verifica dump, poi Carica in xui_migrate (oppure scrivi uno script da eseguire sul server).
  3. Nel pannello XUI: Database Migration → Migrate Database.

Viene scritto solo il database xui_migrate; il database xui in produzione non viene toccato. Le righe di log vengono ignorate perché XUI non le migra.

Importare un backup XUI.one in un altro XUI

La pagina di migrazione di XUI rifiuta i backup XUI ("Can't migrate from XUI to XUI"). Questa funzione importa direttamente nel database xui, via SSH:

  • Ripristina — scegli cosa portare: canali, film, serie, radio, bouquet, linee e dispositivi, rivenditori, EPG, liste di blocco. Vengono sostituiti solo i tipi scelti; il resto rimane com'è.
  • Stream — spostarli tutti sul server principale di questo XUI (ideale per un solo server) oppure aggiungere i vecchi load balancer.
  • Sistema — per impostazione predefinita il nuovo XUI mantiene i propri server, impostazioni e codici di accesso; ognuno può essere importato separatamente.
  • Prima di qualsiasi modifica viene fatto un backup dell'attuale xui sul server (/root/xui-before-import-*.sql.gz) e tutto avviene in una transazione.
  • Alla fine viene creato un accesso di emergenza (codice di accesso + utente admin) e vengono mostrati tutti gli URL del pannello. Salva la password ed elimina l'accesso dopo essere entrato.

Usa sempre prima Anteprima importazione XUI.

Sicurezza

  • Le credenziali vengono copiate così come sono; gli hash delle password non vengono mai decifrati.
  • L'app rifiuta il DROP di un database con dati del pannello senza conferma scritta.
  • Le password MySQL inviate via SSH passano in un file temporaneo protetto, mai sulla riga di comando.

Tema e lingua

Problemi comuni

  • 1130 "Host … is not allowed" — MySQL non accetta il tuo IP: usa una modalità SSH.
  • 1045 "Access denied … (using password: NO)" con root — root accede solo dal socket: scegli SSH + socket MySQL del server.
  • "Can't migrate from XUI to XUI" — il file è un backup XUI.one: usa Importare un backup XUI.
  • Un URL importato non si apre — riavvia XUI o salva di nuovo il codice di accesso nel pannello, così nginx lo ricarica.
