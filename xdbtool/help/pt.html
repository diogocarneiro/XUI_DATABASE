Guia do XUI DB Tool

Versão {version}. Para administradores de painéis IPTV (XUI.one, Xtream UI, StreamCreed, ZapX, Xtream Codes v2) que gerem bases de dados suas ou que estão autorizados a gerir.

Começar

  1. Em Origem dos dados, escolhe uma base de dados em directo (MySQL/MariaDB) ou um ficheiro de dump .sql, e carrega em Ligar / Carregar.
  2. A app identifica o painel e lista as tabelas, com categoria, linhas e colunas. Marca as tabelas com que queres trabalhar (Todos / Nenhum / filtro).
  3. Usa os separadores à direita. O registo em baixo mostra o que está a acontecer.

Botões azuis são as acções principais; botões com contorno vermelho escrevem num servidor (importar, restaurar, migrar, reparar) e pedem sempre confirmação.

Origem dos dados

  • MySQL / MariaDB em directo — host, porta, utilizador, password e base de dados (por exemplo xui). Necessário para manutenção e para exportar o CREATE TABLE.
  • Ficheiro de dump — lê um .sql ou .sql.gz sem servidor. O ficheiro é todo lido para memória; para dumps enormes usa a ligação em directo.
  • Perfis — Guardar grava a ligação (incluindo SSH) para a próxima vez. A password só é guardada se marcares Guardar password no perfil.

Ligação por SSH

O MariaDB do XUI só aceita ligações do próprio servidor (erro 1130 a partir do teu PC). Em Ligar via há três modos:

  • Ligação MySQL directa — só se o servidor aceitar o teu IP.
  • SSH + socket MySQL do servidor — o mais simples no XUI: entra como o mysql -uroot no servidor, sem password MySQL. Indica o host, utilizador e password SSH; deixa a password MySQL em branco.
  • Túnel SSH para MySQL TCP 127.0.0.1 — para utilizadores MySQL com password, por exemplo o do /home/xui/config/config.ini.

Os separadores Templates e Migrar / Restaurar têm a mesma escolha.

Ver e editar dados

Faz duplo clique numa tabela da lista Tabelas (ou selecciona-a e clica em Ver dados…) para abrir as linhas numa janela à parte; podes ter várias tabelas abertas ao mesmo tempo. Funciona com bases de dados em directo e com dumps — numa ligação em directo a pesquisa, a ordenação e as páginas correm no servidor, por isso até tabelas com milhões de linhas abrem logo.

  • Pesquisar encontra as linhas que contêm o texto (sem distinguir maiúsculas) em todas as colunas, ou na coluna escolhida ao lado; Limpar volta a mostrar tudo.
  • Clica no cabeçalho de uma coluna para ordenar por ela; clica outra vez para ordem decrescente.
  • « ‹ › » mudam de página; escolhe de 50 a 1000 linhas por página.
  • Duplo clique numa linha (ou Detalhes da linha…) mostra todas as colunas por inteiro, com as listas JSON, como os canais de um bouquet, formatadas para leitura.
  • Ctrl+C copia as células seleccionadas (separadas por tabulações, prontas para uma folha de cálculo).
  • Passwords, hashes, tokens e chaves aparecem como ••••••; marca Mostrar passwords/chaves para os ver.

Linha de comandos: view streams --dump ficheiro.sql --search sport --columns id,stream_display_name --order id (--json para JSON).

Editar (ligação em directo)

Marca Modo de edição para alterar a tabela no servidor. Está disponível numa ligação em directo, para tabelas com chave primária (a própria chave não é editável — para os IDs dos streams usa Renumerar IDs).

  • Faz duplo clique numa célula (ou começa a escrever) para a alterar; as células editadas ficam amarelas.
  • Adicionar linha acrescenta uma linha vazia (verde): preenche as células que precisares, as outras recebem o valor por omissão da tabela — (auto) marca o ID que o servidor atribui. Duplicar copia as linhas seleccionadas como linhas novas, útil para criar um canal parecido com outro.
  • Apagar / repor marca as linhas seleccionadas para apagar (vermelho, riscadas); clica outra vez para as manter. Pôr NULL esvazia as células seleccionadas.
  • Importar CSV/JSON… acrescenta as linhas de um ficheiro como linhas novas: um CSV com linha de cabeçalho (separado por vírgulas, ponto e vírgula ou tabulações — ficheiros do Excel gravados como CSV funcionam) ou uma lista JSON de objectos. As colunas são associadas pelo nome; as desconhecidas são indicadas e ignoradas; células vazias do CSV recebem o valor por omissão.
  • Nada é escrito até clicares em Guardar alterações…: mostra o que vai mudar e o SQL, e grava tudo numa só transacção. Se o painel tiver alterado alguma dessas linhas entretanto, nada é guardado. É gravado na pasta de exportação um script de desfazer (edit-TABELA-DATA.undo.sql) com os valores anteriores — corre-o com mysql ou em Migrar / Restaurar para voltar atrás.

Os valores são verificados à medida que escreves: números inteiros nas colunas numéricas, JSON válido onde a célula tinha uma lista JSON (canais de bouquets, categorias…), e um aviso antes de texto simples substituir um hash de password (não funcionaria como password). Mudar de página pede para descartar as alterações por guardar. Linha de comandos: edit streams --host … --key id=300 --set stream_display_name="SPORT HD", --delete, --insert --set …, --import linhas.csv, e --dry-run para ver só o SQL.

Exportar / Backup

Exporta as tabelas marcadas em JSON, CSV ou SQL (com CREATE TABLE quando a origem está em directo). Ocultar colunas de passwords/segredos substitui esses valores, útil para partilhar exportações. Faz sempre um backup SQL antes de reparar, migrar ou importar.

Manutenção

Corre Verificar, Reparar, Analisar ou Optimizar nas tabelas marcadas (só com ligação em directo). Verificar e reparar automaticamente verifica todas e repara apenas as que estão danificadas.

Integridade

Os painéis não declaram ligações entre as tabelas, por isso apagar uma categoria, bouquet, servidor ou linha no painel (ou à mão) pode deixar registos a apontar para algo que já não existe. Verificar integridade lê a base de dados inteira (em directo ou dump) e lista:

  • registos que apontam para IDs inexistentes — streams de uma categoria apagada, bouquets com streams apagados, linhas com bouquets apagados, dispositivos MAG/Enigma2 de linhas apagadas, episódios de uma série apagada, streams num servidor apagado…;
  • o mesmo ID repetido dentro da lista de um bouquet ou linha, e listas que não são JSON válido;
  • nomes de utilizador, MACs e códigos de acesso usados por mais de um registo;
  • streams sem nenhum servidor atribuído (não podem ser reproduzidos) e episódios sem série.

Cada problema mostra a sua correcção: apagar estas linhas (registos que só fazem sentido com o que foi apagado), limpar a referência, retirar da lista os IDs inexistentes ou retirar os IDs repetidos. Os restantes são só relatório: revê-os à mão. Desmarca o que não queres corrigir e depois:

  • Guardar script de correcção… — grava o SQL (uma transacção) para correr no servidor; é a única opção para um ficheiro dump;
  • Aplicar correcções seleccionadas — ligação em directo: faz backup SQL das tabelas afectadas na pasta de exportação (integrity-DATA), aplica tudo numa transacção e repete a verificação. Repete até não sobrar nada corrigível: apagar um dispositivo, por exemplo, pode revelar os seus eventos antigos.

Quando a tabela referida está vazia (por exemplo, um dump parcial sem servers) o problema é reportado mas nunca corrigido automaticamente. Linha de comandos: check --dump ficheiro.sql --fix-sql fix.sql, ou check --host … --fix.

Renumerar IDs

Depois de apagar canais antigos, os streams que ficam mantêm IDs altos (por exemplo, o primeiro canal é o 300). Renumerar IDs volta a dar a todos os streams — canais, filmes, rádios e episódios — IDs seguidos a partir de Primeiro ID novo (1), mantendo a ordem actual ou pondo os canais em directo primeiro. Todas as referências são actualizadas: servidores, episódios, opções, bouquets, favoritos MAG, último canal visto e todas as colunas stream_id (logs, fila…).

  1. Corre a Integridade e aplica as correcções: referências a streams apagados cujos IDs iam ser reutilizados bloqueiam a renumeração (nos logs são simplesmente limpas).
  2. Clica em Pré-visualizar: mostra o intervalo de IDs antigo e novo e quantas linhas mudam em cada tabela.
  3. Pára os streams e clica em Renumerar agora (ligação em directo; escreve o nome da base de dados para confirmar). É feito um backup SQL das tabelas afectadas na pasta de exportação (renumber-DATA) e tudo corre numa transacção. Para um dump, usa Guardar script SQL….
  4. Guardar script de renomeação… e corre-o no servidor como root (bash renumber_files.sh): renomeia os ficheiros de filmes/episódios e as pastas do arquivo de TV que têm o ID no nome.
  5. Reinicia o XUI. Os URLs de reprodução mudam (…/live/user/pass/ID.ts): os clientes têm de recarregar a lista M3U.

Linha de comandos: renumber --dump ficheiro.sql --sql-out renumber.sql --files-script files.sh, ou renumber --host … --apply.

Templates / Nova BD

Um template é o schema de uma instalação limpa de um painel. Registar .sql base guarda-o uma vez; depois Criar base de dados a partir do template cria uma base nova e vazia num servidor (por exemplo xui_test). Não uses o nome da base do painel em produção (xui): com DROP marcado ela seria substituída — a app recusa e pede que escrevas o nome para confirmar.

Limpar um template

Um template deve ser uma instalação limpa. Se foi registado a partir da base de um painel real, traz as streams, linhas, contas e logs desse painel (muitas vezes centenas de MB). Selecciona-o e carrega em Limpar template…: a lista mostra cada tabela com linhas e o seu tamanho; as tabelas com dados de um painel — streams, linhas, contas, logs, endereços de servidores, listas de bloqueio — já vêm marcadas, e as tabelas de configuração (settings, grupos, tipos de stream…) mantêm as linhas. Marca ou desmarca o que quiseres, escolhe a chave e o nome novos, e Criar template limpo regista uma cópia com o mesmo schema (as tabelas esvaziadas voltam a numerar os ids a partir de 1). O template original não é alterado.

Reconstruir uma base de dados a partir de um dump

Usa-a quando um backup tem um schema antigo, danificado ou de outra versão: a nova base recebe o schema limpo do template e só os dados das tabelas que escolheres.

  1. Carrega o dump (ou uma base ao vivo) em Origem dos dados.
  2. Marca na lista à esquerda as tabelas a copiar (por exemplo, desmarca os logs).
  3. Escolhe o template — o mais parecido fica seleccionado automaticamente — e escreve o nome da nova base.
  4. Pré-visualizar reconstrução mostra no log o que acontece a cada tabela.
  5. Reconstruir → criar a nova base de dados cria-a no servidor de destino, ou Guardar como ficheiro .sql local… grava a nova base inteira num ficheiro neste computador (.sql, ou .sql.gz comprimido) — não precisa de servidor.

O ficheiro local: com o nome em Nova base de dados cria ele próprio essa base (mysql -u root -p < ficheiro); em branco, é um dump portátil sem nome de base lá dentro — importa-o em qualquer base vazia com o phpMyAdmin → Importar, com Migrar / Restaurar (marca Criar primeiro a base de dados de destino) ou com mysql -u root -p BASE < ficheiro. Também pode ser aberto de novo aqui como Ficheiro de dump SQL.

As colunas correspondem pelo nome: as que só existem no dump são descartadas e as colunas novas do template ficam com o valor por omissão. Uma tabela marcada recebe as linhas do dump; uma tabela que não marcaste fica vazia. Linhas do próprio template decide onde se usam as linhas do template: por omissão só nas tabelas que o dump não tem (novas nessa versão) e nunca linhas, streams ou logs de um template; Em todas as tabelas que não vêm da origem preenche também as não marcadas com as linhas do template; Nenhuma usa só o schema. A pré-visualização mostra o tamanho das linhas do template mantidas e deixadas de fora, e avisa quando um template não é uma instalação limpa (a base de um painel real, muitas vezes com centenas de MB). Por isso marca também as tabelas de configuração de que precisas (settings, grupos, pacotes, tipos de stream…). As tabelas que o template não tem são ignoradas. As linhas são copiadas numa só transacção e os hashes das passwords são copiados tal como estão. A app recusa uma base que já tenha tabelas, a menos que DROP esteja marcado.

Migrar / Restaurar

  • Migrar a origem carregada — copia as linhas para uma base de destino, coluna a coluna (só as colunas que existem nos dois lados). Gerar plano mostra antes o que vai ser copiado; Simulação grava um .sql em vez de escrever.
  • Restaurar um dump — executa um .sql tal como está no servidor de destino, opcionalmente criando a base primeiro.

Migração para XUI (painéis antigos)

Para trazer um painel Xtream UI, ZapX, StreamCreed ou Xtream Codes v2 para o XUI.one, usando a página Database Migration do próprio XUI:

  1. No separador Migração XUI, escolhe o modo SSH, o servidor XUI e o dump antigo.
  2. Verificar dump e depois Carregar para xui_migrate (ou grava um script para correr no servidor).
  3. No painel XUI: Database Migration → Migrate Database.

Só a base xui_migrate é escrita; a base xui em produção não é tocada. As linhas de logs são ignoradas, porque o XUI não as migra.

Importar um backup XUI.one para outro XUI

A página de migração do XUI recusa backups XUI ("Can't migrate from XUI to XUI"). Esta função faz a importação directamente na base xui, por SSH:

  • Restaurar — escolhe o que trazer: canais, filmes, séries, rádios, bouquets, linhas e dispositivos, revendedores, EPG, listas de bloqueio. Só os tipos escolhidos são substituídos; o resto fica como está.
  • Streams — mover todos para o servidor principal deste XUI (ideal para um servidor só) ou adicionar os load balancers antigos.
  • Sistema — por defeito mantém os servidores, definições e códigos de acesso do XUI novo; podes importar cada um em separado.
  • Antes de mudar alguma coisa é feito um backup da xui actual no servidor (/root/xui-before-import-*.sql.gz) e tudo corre numa transacção.
  • No fim é criado um acesso de recurso (código de acesso + utilizador admin) e são mostrados todos os URLs do painel. Guarda a password e apaga o acesso depois de entrares.

Usa sempre primeiro Pré-visualizar importação XUI.

Segurança

  • As credenciais são copiadas tal como estão; os hashes de passwords nunca são decifrados.
  • A app recusa fazer DROP de uma base com dados de painel sem confirmação escrita.
  • As passwords MySQL enviadas por SSH vão num ficheiro temporário protegido, nunca na linha de comando.

Tema e idioma

Tema: Automático (segue o sistema), Claro ou Escuro. Idioma: Português, English, Français, Español, Italiano. As escolhas ficam guardadas.

Problemas comuns

  • 1130 "Host … is not allowed" — o MySQL não aceita o teu IP: usa um modo SSH.
  • 1045 "Access denied … (using password: NO)" com root — o root só entra pelo socket: escolhe SSH + socket MySQL do servidor.
  • "Can't migrate from XUI to XUI" — o ficheiro é um backup XUI.one: usa Importar backup XUI.
  • Um URL importado não abre — reinicia o XUI ou grava de novo o código de acesso no painel, para o nginx o voltar a carregar.
